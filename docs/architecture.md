# 架构草案｜Fantasy Studio 3D v0.1

## 1. 职责边界

**3D 模块负责几何和相机，不负责最终画风。** 输入为可编辑的成年角色模型、Rig、姿势与相机；输出为结构控制数据。2D 画室负责画风模型、LoRA、角色外观、服装生成和最终图像。

- 现有 `body`：人脸专项研究；不能当作已完成的全身基础模型。
- 本仓库：**新**的全身参考与导出工程；不复制旧人脸模型或假定它能直接拼接到全身。
- `2D-generate-beautiful-girl` v1：当前只有文生图、整图 img2img、LoRA；**尚未有** ControlNet、pose/depth/normal 输入或批量风格实验。接口先约定，后接入。
- `3d-scientific-interactions`：科学教学用途，不参与人物建模工程。

## 2. 功能层级

1. **基础网格层**：优先选带权重和成熟 Rig 的合法成人基础模型；体型参数、骨骼一致保存。模型具体来源待评审。
2. **姿势层**：T/A pose 基准，站立、侧身、坐姿、上举手臂、跪姿共五个起始预设；每个姿势具有稳定标识。
3. **形变修正层**：先检查既有权重、双四元数保体积、辅助骨骼；仅对效果不好的肩部、腰腹、胸廓/胸部、骨盆和大腿根做 Corrective Shape Keys，防止过度制作。
4. **观察层**：Blender 内自由旋转、缩放、正侧背视图；表层肌肉走向仅作为可选标记贴图，不建立独立的真实肌肉模拟系统。
5. **导出层**：同一帧、同一相机、同一分辨率的 RGB / Depth / Normal / Pose 预览；另附相机与输出元数据。
6. **连接层**：按明确版本的 manifest 让 2D 画室读取文件；2D 端将来负责将其映射到符合所选 ControlNet 的工作流。
7. **可选轻量查看器**：Three.js/GLB 仅在 Blender 形变和导出完成后评估；复杂 Blender 约束可能需要烘焙，GLB 不保证逐项还原 Blender 材质。

## 3. 数据流

```text
可信成人基础模型 (.blend / .fbx / .glb)
       |
       v
体型 + Rig + 姿势预设 + 相机
       |
       v
Blender 形变审核（权重/辅助骨骼/修正形态）
       |
       v
RGB.png + depth.exr/png + normal.png/exr + pose JSON/PNG
       |                                  |
       +------------- manifest.json ------+
                          |
                          v
                 Fantasy Studio 2D
              (未来的结构控制接口)
                          |
                          v
              三种 2D 插画画风输出
```

Depth/Normal 的色彩空间、数值区间、坐标轴方向不能仅凭文件扩展名推断，应在 manifest 和模型适配器中明确。Pose 关键点使用所选版本映射，不能把 Blender 关节名称直接说成 OpenPose 兼容。

## 4. 设备与存储

- 主设备 Windows + RTX 3060 Ti 8GB；Blender 视图可较轻量，2D ControlNet + 大模型组合需考虑显存。
- 大型模型、贴图、输出与缓存置于 `D:\AI\FantasyStudio\` 等非 C 盘。
- GitHub 不保存重型模型、私人原图、敏感人体素材和第三方训练集。
- 本地图片可被转为结构控制图，但不默认上传云端；本地工具之间应限制目录权限。

## 5. 质量目标

以 5 个预设姿势 + 3 个相机角度测试，优先保证**不严重穿模、关节不塌陷、身体体积自然、姿态可复现**。不承诺任意姿势、极端透视或复杂衣物一开始就正确。

## 6. 明确暂不实现

- 内脏、真实肌腱及肌肉动力学
- 毛孔级皮肤材质与实时软体物理
- 高度交互的网页建模器
- 自动画好精细 2D 角色或达到摄影级外观
- 直接向 ComfyUI v1 发送尚不存在的姿势接口
