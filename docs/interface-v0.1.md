# 2D / 3D 数据接口草案 v0.1

**状态：供评审，尚未由 Blender 真实导出和 ComfyUI 实测。**

目标：把 3D 的**相机、姿势、深度与法线**传给 2D 画室。交换格式优先采用普通文件+JSON，而不是把 Blender 工程直接给 2D。

## 1. 一次导出作为一个包

```text
exports/<export_id>/
├── manifest.json
├── rgb.png
├── depth.exr              # 线性深度建议无损浮点；可额外生成适配预览 PNG
├── normal.exr             # 视坐标或世界坐标必须明示
├── pose-internal.json     # 统一相机投影后的二维关键点
└── pose-preview.png       # 便于人工检查；不是正式骨架原始数据
```

第一版导出的是**单一相机、单一帧**。未来多角度可以多次调用同一姿势导出，每个视角独立一个包。

## 2. 元数据要求

`manifest.json` 的结构参见 `schemas/export-manifest.schema.json` 与 `examples/export-manifest.example.json`。

重要字段：
- `schema_version`：接口版本，初始 `0.1.0`
- `export_id`：该次导出的唯一 ID；不包含个人隐私
- `subject_id`、`pose_id`：关联角色和姿势的稳定标识
- `frame`：Blender 帧编号
- `camera`：投影类型、画幅、相机参数与所用坐标约定
- `outputs`：各个导出文件的相对路径、编码与坐标空间
- `status`：`draft` / `validated`，未通过检查的输出不得冒充已可用

示例只用于检查字段，**不是从真实 Blender 模型导出的样本**。

## 3. 相机一致性

所有图和姿势必须来自**同一场景、同一相机、同一帧**，像素宽高相同。相机内外参、镜头透视及关节投影不能在导出后偷偷改变。

- 投影：将世界坐标的关节先变换到相机坐标，再做透视/正交投影。
- 二维像素以左上角为原点、`x` 向右、`y` 向下；像素坐标适配同样画幅。
- 遮挡关键点可记录可见性/置信度；不要无依据将不可见点标为可见。
- OpenPose 关节布局因工具而异（BODY_25/COCO-18 等），暂用 `pose-internal.json`；**待确定目标 ControlNet 预处理器再做明确映射**。

## 4. 深度与法线

- Depth：建议首先导出相机线性深度浮点 EXR，标记单位及是否正向；所选 ControlNet 要求的 8-bit/16-bit PNG 由**单独适配器**转换，不能假设所有 ControlNet 接收相同编码。
- Normal：应记录为世界空间或相机空间、XYZ 通道、正负区间、色彩空间和坐标轴方向；先用同一个立方体/球体单元测试验证方向。
- RGB：用于人工直观检查，2D 下游不要求使用原图作为图生图底图。

## 5. 接入策略

- **阶段一**：仅生成并校验结构包；2D 项目不改动。
- **阶段二**：在 2D 项目新增“读取结构包 → 选择 ControlNet 型号 → 生成对应节点图”，绝不在当前 v1 中声称已支持。
- **阶段三**：将姿势/相机选择加入简洁 UI；保留手工模式和 AI 模式的素材权限边界。
- ComfyUI 内用与 checkpoint 家族兼容的控制模型；RTX 3060 Ti 8GB 下先单控制输入验证，再逐步叠加。

## 6. 防错

- 使用**相对路径**并检查不得逃出导出目录。
- 文件存在、像素尺寸一致、版本号符合预期。
- 不上传原图、未经授权模型、私人敏感素材或身份信息到 GitHub。
- 任何未通过验证的控制包记录 `status=draft`，不能自动进入稳定画风配方。
