# 3D 体验方案｜姿势与相机必需

> 本文件只记录 3D 技术模块需要向总控提供什么。**用户界面归总控仓库维护**。当前尚无真实可用的全身 3D 操作器或导出程序，不能把独立 HTML 预览当作已集成。

## 核心目标

用户打开统一软件中的 **3D 姿势与取景**，直接看到有体积的人体或简化线稿体块，先通过姿势预设/线稿确定动作，再用虚拟相机调整最终画面。2D 负责最终画风和细节，3D 负责空间参考。

## 3D 的必要接口

| 用户体验 | 3D 模块提供 | 验证重点 |
|---|---|---|
| 选人物/形体 | 模型/基模与稳定 `subject_id`，可选灰模和简单皮肤 | 体积连续，避免明显穿模 |
| 选姿势 | 五种基础姿势、可保存 `pose_id`，后续线稿匹配和调整 | 多视角确认方向一致 |
| 自由观察 | 轨道旋转、平移、缩放 | 不应误改真实相机 |
| **摄影取景（必需）** | **相机位置、朝向/目标点、视角或焦距、透视/正交、画幅比例/分辨率、机位预设与相机保存** | **取景框中的姿势、裁切和透视必须与导出一致** |
| 结构导出 | 同一帧同一相机的 RGB、Depth、Normal、Pose 与 manifest | 相机坐标与像素严格对齐 |
| 送 2D | 输出数据包；配合 2D 适配 ControlNet | 改相机后控制图也随之改变 |

### 相机与观察模式必须分开

- **观察模式**：拖动只是查看模型；不会无意改变最终画面。
- **摄影模式**：拖动/滑条调整真正的输出机位。至少支持正面、侧面、45°、俯视和低机位的基础预设，以及竖版/横版/方形画幅。
- 可以锁定姿势调相机，或锁定相机调姿势；保存机位后可复用。相机参数不能只存在网页预览层，应由 Blender/3D 输出流程使用。
- 注意正交线稿与透视相机的投影差异；不要把图生图“虚拟旋转视角”混作真实模型的相机投影。
- 具体字段与数值格式仍以本仓库 [导出规范](interface-v0.1.md) 为唯一来源；此文件只确认用户体验和能力要求，不再复制一份数据 schema。

## 服装（以后再加，不属于现在的开发任务）

目标只是一个**小型换装辅助能力**：用户上传服装图片 → AI 提取可见款式、颜色、层次和配饰 → AI 根据用户意见反复改预览 → 用户确认 → 才尝试将简化服装附着到人物；如复杂款式尚无合适 3D 网格，可直接将款式图给 2D 参考。

当前无需完整 Marvelous Designer 集成、工业制版、海量材质库或自动布料物理。以后若落地，总控管理图片、修改记录与用户确认；3D 只负责基础服装的几何贴合与导出，2D 负责最终成图。图片本身不能保证自动还原可缝制的准确版型。

## 操作原则

1. 用户先看正常表面，不默认显示骨骼线、权重或节点图；专业检查可切白模、线框、骨架。
2. 手机上手指旋转、双指缩放、少量滑条即可取景，保留恢复默认和保存镜头。
3. 先在 Blender 验证真实姿势及取景一致性，再考虑轻量 Three.js/GLB 浏览层。观察层不必复现 Blender 所有变形器。
4. 总控无法调用 3D 时，2D 仍可独立出图。
