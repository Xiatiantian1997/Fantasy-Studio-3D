# Grok 评审入口｜Fantasy Studio 3D v0.1

这是用户新建并已改名的 **Fantasy-Studio-3D** 仓库。本文件是**首轮评审清单的历史记录**；评审结论已写入 [review-resolution.md](review-resolution.md)。希望你独立评审并提出最小可运行路线；**此阶段先评审，不要未经确认就添加大型模型或自动开始全量处理。**

## 背景

- 目标：原创**成年**女性的可调体型 3D 参考，仅用于给「Fantasy Studio 2D」生成结构控制图；不制作内部器官，不做摄影级软组织模拟。
- 最终美术由 2D 生图模型负责：幻真动漫、半写实 2D、数字油画；将来可增真人类画风，但当前以 2D 为主。
- 硬件：Windows、RTX 3060 Ti 8GB、优先非 C 盘。
- 旧 `body` 已是通用人脸研究库，不在本仓库重构它；3D 教学库也独立。
- 敏感人体资料由你在允许范围内的本地私人模块处理；不要把原始私人素材、敏感局部图片或第三方商业模型提交到 GitHub。

## 请核对八件事

1. **基础模型**：MPFB/MakeHuman 是否足够？是否已有许可清晰、支持商用/私人再加工、权重质量更好的带 Rig 成年人体模型？
2. **形变**：先改善权重、Preserve Volume、辅助骨骼还是优先做 Corrective Shape Keys？五个姿势里哪些局部确实必须修？
3. **体型参数**：身高、肩宽、胸廓/腰臀/腿长与面部形状，哪些参数能不破坏 Rig 地调节？是否应先冻结基准体型？
4. **骨骼控制**：五个姿势如何保存和复现？换姿势后怎么自动检查形变？
5. **导出颜色与数值**：Depth 以相机线性距离保存是否合适？Normal 的坐标空间、EXR/PNG 编码、颜色空间要如何统一？
6. **关节投影**：最少需要哪些关节？应该选 COCO-18、BODY_25 还是内部映射？怎样验证与 ComfyUI 的特定 ControlNet 兼容？
7. **Three.js/GLB**：Morph Targets 实际是支持的，难点主要是 Blender 驱动器、IK、约束及材质的迁移。哪些动作需要烘焙？网页端最小展示范围是什么？
8. **实际工程计划**：一周内先验证什么最小技术闭环？如果遇到模型授权、显存、绑定质量问题，替代方案是什么？不要以时间估计代替验收结果。

## 当前验收方向

- 一个带 Rig 的成年女性基础人体（真实建模完成时才标记完成）
- 站立、侧身、坐姿、举手、跪姿的稳定预设
- 正面/侧面/45° 等多视角检查
- 同一帧 RGB、Depth、Normal、二维姿势控制包
- 画幅、相机参数和控制数据一致
- 由 ComfyUI 实测至少一次 2D 结构控制（待后续集成）

## 希望你返回

1. **同意/不同意** 的技术点，并说明原因。
2. 必需的基础模型及许可证候选，不要虚构下载地址。
3. 项目目录与接口 `docs/interface-v0.1.md` 的具体修改意见。
4. 三个最高风险及低成本缓解方案。
5. 最小验证顺序：先模型/姿势，再导出，再 ComfyUI，再网页查看器。

请区分**已经实现、理论可行、尚需测试**，指出任何你认为我们的设计过度复杂或技术上不成立的部分。
