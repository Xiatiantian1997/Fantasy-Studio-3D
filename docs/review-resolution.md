# Grok 评审处理记录｜2026-11-08

**结论：原则同意，带条件采纳。** 本文仅同步架构审查，不宣称人体模型或导出管线已实施。

## 采纳

- 在选定基础模型之前，就用**举手、坐姿、侧身**对其 Rig、蒙皮和体积保持做压力测试；不合格的模型尽早淘汰。
- **冻结一个基准体型**，先完成 5 个基础姿势的稳定性验证，再开发更大范围的体型参数调整。
- 给每个姿势独立的 `pose_id` 和 Blender Action/预设；姿势不只保存关节旋转，还要保留相关修正参数与测试相机。
- 肩部、胸廓与胸部、腰腹、骨盆/大腿根列为**优先审查区域**；肌肉方向只保留可切换的标记贴图。
- 深度 EXR、法线 EXR 要记录数值语义、坐标空间和方向；先导出简单几何体校准，再导出人体。
- `pose-internal.json` 为内部格式；确认具体目标 ControlNet 后再建立一对一映射和实际可用性测试。
- Blender 验证 → 结构导出 → 2D ControlNet → 可选 Three.js 查看器。

## 不直接照搬的地方

1. **不把形态键列成无条件“必做”。** 先测试原模型权重、辅助骨骼、双四元数蒙皮；不合格区域再用 Corrective Shape Keys / 姿势空间形变修正。某个部位需要什么方法取决于实测。
2. **“必须手工”的范围不能绝对化。** 可以自动采样、检测异常关节角、网格自交候选和姿势前后体积变化；但自动检查不能替代人工审美及解剖质量复核。
3. **Action 并不自动保存所有内容。** 骨架姿势动画、形态键状态、约束驱动与相机关键帧可能属于不同数据通道；导出前要测试完整复现。
4. **导出的正常画面不是控制图兼容性证明。** Schema 通过 ≠ EXR 数值正确 ≠ ControlNet 行为正确。校验分元数据、像素、真实控制效果三级。
5. **角色体型变化会影响已修好的形变。** 先固定基础体型；以后每一种主要体型变体需要额外姿势复核。

## 继续坚持的边界

- 不做内脏和真实软体动力学，不提前做高精皮肤。
- 不搬迁原 `body` 人脸研究的工程，不在公开 GitHub 存私人素材。
- 所有建模和导出完成状态必须有 Blender 真正运行的记录与可复核产物。

## 下一验收

先选候选基础模型，在 Blender 做自然站立、抬手、坐姿的对照。若权重质量不合格，停止在该基础模型上投入形态键制作；重新选型后再继续。
